\section{Axona AI Grounding --- kernel
4.27.1}\label{axona-ai-grounding-kernel-4.27.1}

This file is the complete, self-contained grounding for an AI system
building an application on the Axona protocol. It matches the network it
targets: \textbf{kernel 4.27.1 / wire 4.0, deployed on testnet
(\texttt{wss://testnet.axona.net})}. Everything below is exact and
current; nothing outside this file is required. If this version does not
match the bridge you are connecting to, request the matching grounding
file.

Axona is a serverless peer-to-peer pub/sub network. Every participant is
a peer. Topics are addresses derived from descriptors; messages route to
an emergent per-topic root and fan out through a distribution tree.
There is no central server, message broker, or database.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{HARD RULES --- violations cause silent failure or thrown
errors}\label{hard-rules-violations-cause-silent-failure-or-thrown-errors}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{A topic is a descriptor object, never a string.}
  \texttt{\{\ region?,\ owner?,\ name,\ write?\ \}}. Publisher and
  subscriber must use IDENTICAL fields --- the topic ID is a pure hash
  of them. A mismatch (one names \texttt{region}, the other omits it)
  means two different topics and \textbf{no delivery, with no error}.
\item
  \textbf{Every publish names its signer.}
  \texttt{peer.pub(topic,\ msg,\ \{\ signWith\ \})} ---
  \texttt{signWith} is an author identity or the \texttt{ANONYMOUS}
  sentinel. Omitting it throws \texttt{PUBLISH\_NO\_PUBLISH\_IDENTITY}.
  There is no default signer.
\item
  \textbf{Two identities, never interchangeable.} The \emph{node}
  identity (\texttt{createNodeIdentity}) is the connection --- it has a
  location and forms the node ID; it NEVER signs content. The
  \emph{author} identity (\texttt{createAuthorIdentity}) signs content
  --- it has NO location and NO node ID.
\item
  \textbf{\texttt{await\ peer.ready()} before first pub/sub.} Publishing
  on a cold mesh is survivable (the kernel retries) but unpredictable.
  \texttt{ready()} resolves when the routing mesh is warm.
\item
  \textbf{A publish returns no delivery acknowledgment --- ever.} This
  is a privacy invariant (author and transport identities must stay
  uncorrelated). To confirm delivery, subscribe to the topic yourself
  and watch for your own \texttt{msgId} to arrive.
\item
  \textbf{Message payloads: 15 KB is the reliable cross-browser floor.}
  Hard ceiling 256 KB, but anything over 15 KB may fail on real WebRTC
  channels. For larger payloads use \texttt{std/chunk} (below), never a
  bigger single publish.
\item
  \textbf{Messages expire.} Default hold \textasciitilde24 h (48 h
  ceiling). Re-publishing the identical payload from the same author
  yields the SAME msgId and refreshes the hold (an upsert; subscribers
  are not re-notified). Axona is a live messaging fabric, not permanent
  storage.
\item
  \textbf{\texttt{kill} is the only retraction} and its signature is
  \texttt{peer.kill(topic,\ msgId,\ \{\ signWith\ \})} --- the
  \textbf{descriptor comes first}, exactly like \texttt{pub}.
  \texttt{peer.kill(msgId)} (omitting the topic) is the most common
  mistake observed in the field and throws. The kill must be signed by
  the same author key that signed the original, and is best-effort
  (receivers already holding the plaintext keep it). Anonymous messages
  cannot be killed. \texttt{unpub} and \texttt{touch} do not exist in
  4.x --- do not call them.
\item
  \textbf{Persist the author key if user identity should survive
  restarts.}
  \texttt{createAuthorIdentity(\{\ persistAs:\ \textquotesingle{}myapp:author\textquotesingle{}\ \})}
  (browser localStorage). Everything else (node identity, subscriptions)
  can be ephemeral and re-created each run.
\item
  \textbf{Node 20+ or a browser over HTTPS.} The kernel needs Web Crypto
  (\texttt{crypto.subtle}) and ES modules. No build step, no bundler
  required.
\end{enumerate}

Delivery semantics an app can rely on: - Exactly-once per \texttt{msgId}
to each subscriber handler. - Publishing again with the identical
payload + author = same \texttt{msgId} = refresh, not a duplicate
delivery. - Late subscribers with
\texttt{since:\textquotesingle{}all\textquotesingle{}} receive cached
history (bounded queue, \textasciitilde24 h) then the live tail. - The
kernel retries a publish internally until it confirms placement; a
freshly-joined publisher gets an extra rapid burst. Your code does not
retry.

TIMING RULES (metrics are published ON DEMAND --- the subscribe itself
turns them on; there is no always-on publisher):

\begin{itemize}
\tightlist
\item
  First snapshot: at ROUTING LATENCY (\textasciitilde0.3 s typical;
  allow a few seconds under churn) --- the root answers the moment the
  lease arms, independent of other users' publish/watch activity.
  Cadence: every \textasciitilde20 s while subscribed. Publishing stops
  \textasciitilde70 s after the last metric subscriber leaves.
\item
  \texttt{peer.metrics()} (one-shot) normally succeeds within its 1.5 s
  default window; \texttt{stale:\ true} means the answer didn't arrive
  in time (churn) --- retry or prefer the standing \texttt{sub()} form.
\item
  Render silence as UNKNOWN, never as zero: a
  \texttt{current\_count:\ 0} snapshot is the real ``no activity''
  answer. Keep the subscription open in tests.
\end{itemize}

Metrics are advisory (unauthenticated counts) --- never a security
input.

\subsection{Field-observed mistakes --- every one of these has shipped
in a real
app}\label{field-observed-mistakes-every-one-of-these-has-shipped-in-a-real-app}

Check generated code against ALL of these before calling it done.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{\texttt{peer.kill(msgId)} --- topic omitted.} Every content
  operation takes the \textbf{descriptor first}:
  \texttt{kill(topic,\ msgId,\ \{\ signWith\ \})}, exactly like
  \texttt{pub(topic,\ …)} / \texttt{sub(topic,\ …)}. There is no id-only
  form of anything.
\item
  \textbf{Reconnecting the peer to switch users/personas.} WRONG:
  tearing down the connection when the active author changes (it churns
  the mesh and drops live WebRTC links mid-ICE). One peer serves ANY
  number of authors --- authorship is chosen per call via
  \texttt{\{\ signWith\ \}}. Reconnect only when the bridge URL changes.
\item
  \textbf{Sharing a topic without its full descriptor.} An invite,
  directory ad, QR code, or link that transmits only \texttt{name} (or
  name + region) sends the recipient to a DIFFERENT topic whenever the
  original has an \texttt{owner} ---
  \texttt{\{region,\ owner,\ name,\ write\}} ALL fold into the topic id
  (HARD RULE 1). Always transmit the complete descriptor.
\item
  \textbf{Deriving presence/recency from arrival time.} A
  \texttt{since:\textquotesingle{}all\textquotesingle{}} (or
  \texttt{\textquotesingle{}latest\textquotesingle{}}) subscription
  replays history: a message that arrives NOW may have been published
  hours ago. Recency logic (online lists, ``last seen'') must read
  \texttt{env.ts} (publish time), never the local clock at delivery. For
  ephemeral signals like heartbeats, subscribe with \texttt{since}
  omitted (live-only) --- replaying stale heartbeats is pure noise.
\item
  \textbf{Faking encryption with public inputs.} The protocol signs
  messages; it does NOT encrypt them, and it provides NO
  encrypt-to-author primitive. An author ID is \textbf{public} (it is
  \texttt{env.signerPubkey} on every signed message) --- any scheme that
  derives a decryption key from it is plaintext with extra steps.
  Confidentiality needs a real app-layer key exchange (e.g.~keys
  delivered out-of-band, or a proper ECDH scheme); if you cannot do
  that, say so in the UI rather than shipping theater.
\item
  \textbf{Inventing a fallback when derivation fails.} If
  \texttt{deriveTopicId} (or any kernel call) throws, surface the error.
  Substituting a locally-made-up id ``so the UI keeps working'' silently
  diverges that client from every other peer on the topic --- the
  failure mode is invisible no-delivery (HARD RULE 1).
\end{enumerate}

\subsection{Troubleshooting rules}\label{troubleshooting-rules}

\begin{itemize}
\tightlist
\item
  \textbf{Connected but nothing arrives} → publisher and subscriber
  derived different topic IDs. Diff the descriptors field-by-field
  (including an omitted vs named \texttt{region}), or → published before
  \texttt{ready()}.
\item
  \textbf{\texttt{Cannot\ mix\ BigInt\ and\ other\ types}} → pre-4.14
  kernel with a hex id passed to \texttt{NeuronNode}; on this version
  the hex id is accepted directly (and \texttt{connect()} avoids the
  question entirely).
\item
  \textbf{Works on localhost, fails deployed} → page not HTTPS
  (\texttt{crypto.subtle} unavailable).
\item
  \textbf{Firefox only: ``ICE failed, your TURN server appears to be
  broken'' repeating, peers stuck at \textasciitilde1, no delivery} →
  the dev server is bound to IPv6 loopback (\texttt{::1}) --- Vite's
  default. Firefox gathers ZERO ICE candidates on a \texttt{::1}-origin
  page, so every mesh dial fails; Chromium is unaffected. Fix:
  \texttt{server:\ \{\ host:\ \textquotesingle{}127.0.0.1\textquotesingle{}\ \}}
  in \texttt{vite.config.js} (or serve on an IPv4 address). The TURN
  server is fine --- do not debug it.
\item
  \textbf{Large message silently missing for some receivers} → over the
  15 KB reliable floor. Use \texttt{std/chunk}.
\item
  \textbf{User identity resets every reload} → author not persisted. Use
  \texttt{createAuthorIdentity(\{\ persistAs\ \})}.
\item
  \textbf{WS close 4426} → version mismatch; reinstall the pinned tag.
\end{itemize}
